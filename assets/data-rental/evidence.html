1. The promise

The computation party built its computation into a container image and published the image's digest. The digest covers every byte of the image, including the code and the public key results are sealed to.

sha256:662efdda7a0630462c79f5ef1a7451f2b44022845972a39f0e3c06ca55fca243

The data owner approved that digest. Their key pool on Google Cloud releases the dataset key only when an attestation token shows all of these:

assertion.swname == 'CONFIDENTIAL_SPACE'
&& assertion.submods.container.image_digest == 'sha256:662efdda7a0630462c79f5ef1a7451f2b44022845972a39f0e3c06ca55fca243'
&& 'demo-vm@cdr-sandbox-1012.iam.gserviceaccount.com' in assertion.google_service_accounts

2. The imposter differs by one line

The same computation, plus one line that copies raw records into the output.

+ "raw_records": [json.loads(l) for l in shard.decode().splitlines()[:20]],  # ADDED: leak raw data

One changed line gives an unrelated digest, so the imposter can't pass as the promise.

4. The imposter was refused

The operator launched the imposter on the same kind of VM. The harness inside the image makes no check of its own; it simply asked for the key. Google's key release compared the attested digest with the promise and refused, so the image never held the key and never decrypted a record.

job failed before reading data: RetryError: Timeout of 60.0s exceeded, last exception: 503 Getting metadata from plugin failed with error: ('Error code unauthorized_client: The given credential is rejected by the attribute condition.', '{"error":"unauthorized_client","error_description":"The given credential is rejected by the attribute condition."}')

How the binding works

  1. The data owner encrypts the records and wraps the data key with Cloud KMS. Only their key pool can unwrap it, and only for an attested VM.
  2. Confidential Space measures the image the VM boots and puts its digest in a token signed by Google. The operator can't change the digest it reports.
  3. The pool trades that token for credentials only if the digest equals the promise. Any other image gets no credentials and so no key.

This run used throwaway keys and the debug image, which keeps logs visible. A production run uses the hardened image and keys that refuse debug images.

The binding guarantees which code touches the data, not what that code does. The owner relies on the promised image's behavior, for example after an audit of its source.
